📚 RAG Integration

Retrieval-Augmented Generation enhances two LLM steps. The RAG layer is deterministic (BM25 + substring matching) — no vector database or embeddings API.

🔍 How RAG Feeds Into the Pipeline

BM25 Exemplar Search

37 labeled articles indexed with BM25. For each new article, the top 3 by keyword similarity are selected as dynamic few-shot examples.

→ Monitoring Agent prompt + CSCO Summary prompt

Entity Grounding

Company names in the article are matched against 2,900 nodes in the knowledge graph (exact + fuzzy). Matched companies get their verified industry and country.

→ Monitoring Agent prompt + CSCO Summary prompt

Monitoring Agent

Receives examples showing "how similar articles were correctly analysed" + grounded entity records. Prevents over-generalization and buyer/producer confusion.

Result: more precise extraction

CSCO Summary

Receives the same RAG context so the executive summary references verified entities and patterns from similar past disruptions.

Result: more informed executive summary

🔄 Human-AI Feedback Loop

When the reviewer isn't satisfied, the pipeline doesn't dead-end — it loops back with corrections.

🔀 Decision Routes from Human Review

✅ Approve

Accept the analysis as-is. Pipeline continues to Alternative Sourcing to find replacement suppliers for HIGH-risk ones.

→ alternatives → END

✏️ Approve with Edits

Modify the executive summary or change supplier action levels (HIGH/MEDIUM/LOW), then proceed to alternatives.

→ alternatives → END

🔄 Send Feedback & Re-analyse

Write what's wrong (e.g., "Japan is only a buyer"). The AI re-reads the article with this feedback injected into the prompt. Up to 3 rounds.

→ monitoring (full re-run with feedback + RAG)

⚙️ Edit Extraction Directly

Fix countries/industries/companies by hand. Skips the LLM entirely — only re-runs KG query, risk scoring (with reasoning), visualization, and summary.

→ kg_query (skips LLM, much faster)

🛑 Discard Analysis

Hard stop. The analysis is thrown away. Use when the article is irrelevant or fundamentally misunderstood.

→ END

📊 Risk Scoring with Reasoning

Every Tier-1 supplier gets a risk score (0–1) with a human-readable explanation of why it's scored that way. The formula:

score = 0.35 × breadth + 0.25 × dependency + 0.20 × criticality + 0.10 × centrality + 0.10 × depth
Breadth (35%)
How many disrupted suppliers sit upstream, weighted by proximity
Dependency (25%)
Share of this Tier-1's direct inputs that are disrupted or lead to disruption
Criticality (20%)
PageRank and degree centrality of the most critical disrupted node upstream
Centrality (10%)
How well-connected this Tier-1 is relative to other Tier-1 suppliers
Depth (10%)
How deep in the supply chain the disruption reaches (Tier-2, 3, 4)
Example Reasoning Output
Sakri Packaging 020: HIGH (0.613) — directly disrupted (is itself in the affected region/industry); high criticality — a critical node in the network; high centrality among Tier-1 suppliers

The network diagram shows the supply chain graph with nodes colored by risk level. Every node and edge has reasoning tooltips:

Hover a Node

Hover an Edge
